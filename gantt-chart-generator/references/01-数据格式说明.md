# 数据格式说明

## 一、支持的输入格式

| 扩展名 | 说明 |
|---|---|
| `.csv` | UTF-8（带/不带 BOM 均可），分隔符自动识别 `,` `;` `Tab` |
| `.xlsx` | 读取第一个工作表，首行为表头（需 openpyxl） |
| `.json` | 顶层为数组，或 `{"tasks": [...]}` |

## 二、字段完整定义

列名不区分大小写、忽略空格与下划线；中英文别名等价。

| 标准字段 | 中文别名 | 英文别名 | 类型 | 说明 |
|---|---|---|---|---|
| `wbs` | WBS、编号、大纲号、层级编码 | wbs | 文本 | 建议格式 `1`、`1.2`、`1.2.3`；点号数量决定层级缩进 |
| `name` | 任务名称、任务名、名称、工作名称、工序 | name | 文本 | **必填** |
| `type` | 类型、任务类型 | type | 枚举 | `任务`(默认) / `摘要`(阶段) / `里程碑`；别名：task / summary / milestone / 节点 / 关键节点 / phase |
| `start` | 开始日期、开始时间、计划开始、开工日期 | start | 日期 | |
| `end` | 结束日期、完成日期、竣工日期、截止日期 | end | 日期 | |
| `duration` | 工期、天数、持续天数 | duration | 整数 | 单位：工作日（默认）或自然日 |
| `progress` | 进度、完成度、完成百分比、完成率 | progress | 数值 | `0-100`、`0-1`、`85%` 三种写法均可 |
| `assignee` | 负责人、责任人、执行人、承担人 | assignee、owner | 文本 | |
| `resources` | 资源、参与人、人员、团队 | resources | 文本 | |
| `deps` | 前置任务、前置、依赖、紧前任务、前序任务 | deps、predecessors | 文本 | 见第三节语法 |
| `deptype` | 依赖类型、关系类型 | deptype | 枚举 | `FS`/`SS`/`FF`/`SF`，未在 deps 中指定时生效 |
| `lag` | 滞后、滞后天数、延隔、延迟 | lag | 整数 | 正数表示延迟，负数表示提前搭接 |
| `color` | 颜色、色彩 | color | 文本 | 十六进制如 `#3B82F6`；不填自动配色 |
| `baseline_start` | 基线开始、基准开始 | baseline_start | 日期 | 与 baseline_end 成对使用 |
| `baseline_end` | 基线结束、基准结束 | baseline_end | 日期 | |
| `notes` | 备注、说明、描述 | notes、remark | 文本 | 悬浮提示中显示 |
| `milestone` | 里程碑、是否里程碑 | milestone | 布尔 | `是`/`Y`/`1`/`true` 均可 |
| `priority` | 优先级 | priority | 文本 | |

> 未识别的列会被忽略，不会报错。

## 三、日期写法

脚本兼容以下格式，自动解析：

```
2026-03-02          2026/03/02          2026.03.02
2026年3月2日         20260302           2026-03-02 09:00:00
3月2日               （补当前年份）
46112                （Excel 日期序列号）
```

也支持区间写法，取起始值：`2026-03-02至2026-03-20`。

## 四、依赖语法详解

写在「前置任务」列中，多条用 `,` `;` `、` 分隔。

### 基本形式

| 写法 | 含义 |
|---|---|
| `1.2` | 前置为 WBS=1.2 的任务，关系 FS，滞后 0 |
| `T5` | 用任务编号引用 |
| `基础开挖` | 用任务名称引用 |
| `1.2:SS:3` | 关系 SS，滞后 3 天 |
| `1.2 FS 2` / `1.2(FS,2)` | 等价写法 |
| `1.2;1.5` | 两个前置任务，都按 FS |

### 四种关系

| 代号 | 名称 | 语义 | 约束公式 |
|---|---|---|---|
| `FS` | Finish-to-Start | 完成-开始 | `后续.开始 ≥ 前置.结束 + 1 + 滞后` |
| `SS` | Start-to-Start | 开始-开始 | `后续.开始 ≥ 前置.开始 + 滞后` |
| `FF` | Finish-to-Finish | 完成-完成 | `后续.结束 ≥ 前置.结束 + 滞后` |
| `SF` | Start-to-Finish | 开始-完成 | `后续.结束 ≥ 前置.开始 + 滞后` |

> 滞后以工作日计（`--calendar workday`），可为负值表示搭接。

### 典型用法

- **串行**：`A → B`，B 的前置写 `A`（FS，默认）
- **搭接施工**：B 在 A 开始 3 天后启动 → B 的前置写 `A:SS:3`
- **缓冲期**：A 完成后隔 2 天再做 B → B 的前置写 `A:FS:2`
- **汇合**：C 要等 A 和 B 都完成 → C 的前置写 `A;B`

## 五、类型说明

| 类型 | 视觉表现 | 用途 |
|---|---|---|
| `任务` | 圆角条 + 进度填充 | 普通工作项 |
| `摘要` | 深灰细条 + 两端三角 | 阶段/父任务，日期工期由子任务自动汇总 |
| `里程碑` | 橙色菱形 ◆ | 关键节点/评审/验收/上线等零工期事件 |

**层级识别**：优先按 `WBS` 的点号数量；没有 WBS 时按 `层级` 列；都没有则同级。
摘要任务后面的同级或更深任务自动归为其子任务（按出现顺序用栈解析）。

## 七、JSON 输入

```json
{
  "project": { "name": "示例项目" },
  "tasks": [
    { "id": "T1", "wbs": "1.1", "name": "需求调研", "type": "task",
      "start": "2026-03-02", "end": "2026-03-13", "progress": 100,
      "assignee": "张伟", "deps": [], "notes": "" },
    { "id": "T2", "wbs": "1.2", "name": "需求评审", "type": "milestone",
      "start": "2026-03-16",
      "deps": [{ "id": "T1", "type": "FS", "lag": 0 }] }
  ]
}
```

JSON 模式下 `deps` 直接写数组，元素为 `{"id": "...", "type": "FS", "lag": 0}`。
