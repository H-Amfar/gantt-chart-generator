# 与 Microsoft Project 的功能对照

本 Skill 的目标是覆盖 Project 中最常用的进度计划能力，并针对「快速出图、便于分享、AI 可直接生成」做取舍。

## 一、功能对照总表

| 功能域 | Microsoft Project | 本 Skill | 状态 |
|---|---|---|---|
| **任务清单** | 任务表、WBS 大纲分级 | CSV/Excel/JSON 输入，WBS 点号自动分级 | ✅ 支持 |
| **任务类型** | 常规任务 / 摘要任务 / 里程碑 | `任务` / `摘要` / `里程碑` | ✅ 支持 |
| **工期** | 工作日/分钟/小时，可自定义 | 工作日（跳周末、可设节假日）或自然日 | ✅ 支持 |
| **日历** | 项目日历、资源日历、任务日历 | 项目级日历（工作周 + 节假日） | ⚠️ 部分 |
| **任务依赖** | FS / SS / FF / SF + 滞后/提前 | 四种关系 + 正负滞后 | ✅ 支持 |
| **自动排程** | 自动/手动排程模式 | 无日期任务按依赖自动推导 | ✅ 支持 |
| **摘要汇总** | 父任务自动汇总日期与工期 | 自动汇总日期、工期、加权进度 | ✅ 支持 |

| **导入导出** | MPP / XML / Excel | CSV / Excel / JSON 输入；HTML/PNG/JSON 输出 | ✅ 支持 |

## 二、重点功能的实现说明

### 2.1 自动排程逻辑

```
无「开始日期」的任务 → 按前置依赖 + 滞后 + 工作日历推导开始日
有「开始日期」的任务 → 视为人工锁定，保持不变（等价于「手动排程」）
有开始+工期 → 结束日按工作日历推进（自动跳过周末）
有开始+结束 → 工期按工作日数反推
只有工期无日期 → 由前置决定开始，无前置则从项目起始日开始
```

### 2.2 关键路径算法

采用标准 CPM 双向计算，且**在工作日序数空间**进行，因此跨周末不会误判：

1. **前推**（正序拓扑）：计算每个任务的 `ES`（最早开始）、`EF`（最早完成）
2. **后推**（逆序拓扑）：以项目最晚完成日为 `LF`，反算 `LS`（最晚开始）、`LF`
3. **总浮动** `TF = LS - ES`，`TF ≤ 0` 的任务构成关键路径

这与 Project 的判定口径一致：关键路径上的任务没有可推迟的余地。

### 2.3 里程碑（关键节点）

标记为 `里程碑` 的任务：

- 工期强制为 0
- 以**橙色菱形**绘制，名称标注在右侧
- 可作为关键节点承接前后依赖，常用于：评审通过、节点验收、上线、竣工
- 支持作为依赖的起点或终点

### 2.4 滞后的语义

沿用 Project 定义：`FS` 关系默认「前置完成后次日开始」。

| 写法 | 含义 |
|---|---|
| `A` | B 在 A 完成后次日开始 |
| `A:FS:0` | 同上一行 |
| `A:FS:2` | A 完成后**再等 2 个工作日**，B 才开始（共隔 3 天） |
| `A:SS:3` | A 开始 3 个工作日后 B 才开始（搭接施工） |
| `A:FS:-1` | 负滞后，B 与 A 重叠 1 天 |

## 三、本 Skill 的差异化优势

| 维度 | Project | 本 Skill |
|---|---|---|
| 上手成本 | 需安装、需学习 | 说一句话或给一份表即可出图 |
| 生成的图 | 截图或手动导出 | 交互式 HTML，可缩放、可拖拉改期 |
| 分享 | 对方需装 Project | 一个 HTML 文件，双击就可看 |
| 嵌入报告 | 需手动截图 | 一条命令同时出 PNG |
| AI 协作 | 不直接支持 | 对话中描述任务即可直接落图 |
| 依赖可视化 | 有 | 有，关键路径用红线强化 |

## 四、已知限制与规避方式

| 限制 | 规避方式 |
|---|---|
| 无多基线对比 | 需要对比多个版本时，导出多次并排查看 |
| 无资源工时/成本核算 | 负责人字段仅作标注，成本需外部表格计算 |
| 无自由浮动（Free Slack） | 目前只算总浮动；如需可后续扩展 |
| 无资源过度分配检测 | 需要时在 Excel 中做透视检查 |
| 不支持 .mpp 格式互转 | 用 CSV/Excel 作为中转格式 |
| 大型项目（>300 行）性能 | 建议在 Excel 中先按阶段汇总后再生成，或按阶段拆分多张图 |
